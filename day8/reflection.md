# Reflection

The most difficult concept in this course was understanding how to design a system that can handle a large number of users without compromising correctness. At first, concepts such as database transactions, caching, load balancing, and horizontal scaling seemed complicated because they involve different components working together. I overcame this challenge by breaking the system into smaller parts, studying the responsibility of each component, and applying the concepts in my QuickNotes capstone. Designing API endpoints, database tables, and an architecture diagram helped me understand how individual components contribute to the overall system.

Based on the feedback I received, I would improve the scalability and reliability analysis of my capstone. I would include more detailed traffic estimates, clearer explanations of potential bottlenecks, and a more practical plan for testing the application under heavy traffic. I would also strengthen error handling and security considerations so that the system is not only functional but also dependable when unexpected problems occur.

Next, I want to learn backend development and database implementation in greater depth. I would like to build a working REST API, connect it to a relational database, implement authentication, and learn how to test API performance under load. I also want to explore cloud deployment, monitoring, and automated testing. These skills will help me move from designing systems on paper to building, deploying, and maintaining reliable applications that solve real-world problems.
